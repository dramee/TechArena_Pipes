# Specification: Gas Pipeline Construction Project

## Проект описание
Это решение для задачи о прокладке подземного газопровода в Китай. Проект реализует онлайн-алгоритм управления специальной машиной (CNC pipelayner), которая копает траншеи и укладывает трубы, оптимизируя KPI (отношение суммы длин уложенных труб к длине вырытой траншеи).

**Основная задача описана в файле: `1.pdf`**

---

## Структура проекта

### 📁 Корневые папки

#### `dump/` 
Папка с результатами анализа тестов. Содержит CSV-файлы с детальной информацией о каждом из 15 открытых тестов (1.in.csv - 15.in.csv), включая:
- Координаты укладки каждой трубы
- Статус пайпа (уложена/удалена)
- Анализ использования траншеи
- KPI для каждого теста

#### `myTests/`
Папка для локально сгенерированных тестов (тесты 16-85), создаваемых скриптом `generate_tests.py`.

#### `tests/`
Папка с 15 открытыми тестами проекта (1.in - 15.in). Это официальные тест-кейсы от задания.

#### `.git/`
Git-репозиторий проекта для версионирования.

#### `.idea/`
Конфигурация IDE (JetBrains).

#### `.venv/`
Виртуальное окружение Python для зависимостей.

## 📄 Python файлы (.py)

### `runner.py`
**Назначение:** Основной тестер локального запуска решения против интерактора.

**Функциональность:**
- Запускает скомпилированное решение через интерактор (interactor.exe/interactor)
- Собирает метрики CPU time и память (через psutil)
- Читает результат KPI из файла score.txt
- Форматирует и выводит результаты тестирования

**Использование:**
```
python runner.py -d tests <binary>           # запустить на всех тестах в папке tests
python runner.py -i tests/1.in <binary>      # запустить на конкретном тесте
```

### `generate_tests.py`
**Назначение:** Генератор локальных тестов (тесты 16-85) для дополнительной проверки решения.

**Функциональность:**
- Генерирует тесты с различными паттернами:
  - Обычные тесты (16-65): разные вероятности удаления, LIFO/random, разные диапазоны длин
  - Стресс-тесты (66-85): большие объемы операций (100K-200K команд)
  - Периодические тесты: повторяющиеся блоки с удалениями по шаблону
- Сохраняет тесты в формате `.in` в папку `myTests/`
- Устойчив к рандомизации через seed

### `run_all.py`
**Назначение:** Скрипт для пакетного запуска всех тестов с агрегацией результатов.

**Функциональность:**
- Компилирует `solution.cpp` (`g++ -O2`) во временную папку или берёт готовый бинарник первым аргументом
- Прогоняет решение через `interactor` на всех тестах из `tests/` и `myTests/` (по одному, с таймаутом)
- Для каждого теста сохраняет вес, балл, KPI, время и CPU-время самого решения (без интерактора)
- Считает итоговый KPI = Σ score / Σ weight и суммарное/максимальное CPU-время
- Пишет `kpi_results.csv` (по тестам) и `kpi_results.json` (итог)

**Использование:**
```
python run_all.py                          # скомпилировать solution.cpp и прогнать tests/ и myTests/
python run_all.py ./solution -d tests      # готовый бинарник, только открытые тесты
```

## 📄 C++ файлы (.cpp)

### `solution.cpp`
**Назначение:** ОСНОВНОЕ РЕШЕНИЕ - интерактивный решатель задачи о трубопроводе.

**Архитектура:**
- **Режим 1 (Best-Fit):** Стандартный алгоритм размещения труб с поиском наилучшей подходящей щели:
  - Приоритет точного совпадения размера
  - Порог остатка KMIN: 4 первые 500 труб, затем 24 (остаток < 20 м — мёртвая дыра для длинных труб)
  - На коротких траншеях (≤ 100 м) бережёт самую правую точную дыру

- **Режим 2 (Фазовый анализ):** Обнаружение паттернов удаления:
  - Детектирует пачки одинаковых труб (MIN_RUN >= 20 шт.); пачка кончается при смене длины
    или после всплеска удалений (повторяющиеся пачки одной длины разбираются по отдельности)
  - Выявляет периодический паттерн удаления (период 2-8)
  - Предварительно копает под ожидаемый остаток пачки, но без подтверждённого прогноза —
    не больше уже уложенного в пачке
  - Размещает трубы оптимально (удаляемые в конец, остающиеся в начало)

- **Режим 3 (Предсказание периодичности):** Обнаружение регулярных последовательностей:
  - Если входящие трубы образуют периодическую последовательность
  - Предполагает удаление труб с четными номерами внутри периода
  - Размещает трубы для максимального освобождения блока при удалении
  - Проверяет точность предположения и отключает если оно некорректно

- **Режим 4 (Выученная судьба позиций периода):**
  - Период ищется по всем укладкам подряд (удаления его не сбрасывают)
  - Каждую трубу «судят» через 64 укладки: удалили её за это время или нет
  - Если каждая позиция периода удаляется в ≥ 80% случаев или в ≤ 20%, укладка по шаблону:
    остающиеся — в дыру точно по размеру, иначе в хвост траншеи; обречённые — best-fit
    (переиспользуют места прошлых обречённых); хвост копается сразу под обречённые трубы периода
  - Отключается навсегда, если прогнозы ошибаются чаще чем в 20% случаев

**Ключевые компоненты:**
- Дыры хранятся в массивах по позиции (начало → длина, конец → начало) и в корзинах по размеру
  (1..40 и «больше 40»); склейка соседних дыр при удалении — O(log n)
- Ответы интерактору формируются вручную и сразу сбрасываются (`fwrite` + `fflush`), ввод — без блокировок stdio
- Поддержка режима SIM (симуляция без интерактора) через флаг -DSIM: тест читается из stdin,
  KPI печатается в stderr

**Производительность:**
- CPU time limit: < 5 секунд
- Memory limit: < 256 MB

### `offline.cpp`
**Назначение:** Офлайн-анализатор и оптимизатор (знает будущее).

**Функциональность:**
- Читает полный тест с явной информацией о моментах удаления
- Вычисляет несколько стратегий:
  - **LB** — нижняя граница: максимальная сумма одновременно лежащих труб
  - **online** — обычный best-fit (для сравнения)
  - **oracle** — best-fit с знанием будущих удалений
  - **exact** — полный перебор для доказательства оптимума (для малых тестов)

- Генерирует отчеты и дампы для анализа стратегий
- Помогает понять верхнюю границу KPI

**Использование:**
```
./offline [--dump dir] [--w2 X] [--k N] [--max-exact-events N] tests/*.in
```

### `interactor.cpp`
**Назначение:** Интерактор — промежуточная программа для общения решения с тестовой системой.

**Функциональность:**
- Имитирует работу системы управления пipelayer
- Читает команды от решения (укладка, удаление)
- Проверяет корректность команд
- Отслеживает состояние траншеи и труб
- Вычисляет итоговый KPI
- Сообщает об ошибках взаимодействия

**Логика:**
- Размер траншеи изначально 0
- Копание увеличивает траншею на N×20 метров
- Проверяет, что трубы не выходят за границы
- Отслеживает PID каждой уложенной трубы
- Вычисляет финальный KPI по формуле: (сумма длин оставшихся труб) / (длина траншеи)

### `sim.cpp`
**Назначение:** Сравнение простых политик укладки на тестах без интерактора (отдельно от `solution.cpp`).

**Функциональность:**
- Читает тесты из файлов, прогоняет на каждом набор политик и печатает таблицу KPI,
  среднее, взвешенное среднее и score
- Политики: best/first/worst/last-fit, best-fit с порогом остатка (`bestK-left`),
  SIGMA3 (классы по правилу 3σ, worst-fit для маленьких, с условиями включения `g:*`),
  классы Мартелло–Тота относительно дыры с парами MTRP (`mt:*`)
- Фазовых и периодических режимов `solution.cpp` в нём нет — это стенд для сравнения выбора дыры

**Использование:**
```
./sim tests/*.in                                  # все политики
./sim --only bestK-left,s3:KK,mt:q10p2 tests/*.in # только выбранные
```

## 🔄 Workflow решения

1. **Интерактор** отправляет команду: длина трубы L или удаление -K
2. **Solution.cpp** получает команду
3. Выбирает стратегию (режим 1, 2 или 3) в зависимости от контекста
4. Вычисляет оптимальную позицию D и необходимое копание N
5. Отправляет ответ "N D" (для укладки) или "D" (для удаления)
6. **Интерактор** проверяет корректность, обновляет траншею
7. Процесс повторяется до команды 0
8. Вычисляется финальный KPI

## 📈 Оптимизационные стратегии

### Режим 1: Best-Fit (Основной)
- Ищет наилучшую щель для текущей трубы
- Минимизирует фрагментацию через адаптивный KMIN
- Работает хорошо на случайных распределениях

### Режим 2: Фазовый (Специальный случай)
- Обнаруживает повторяющиеся последовательности одного размера
- Предсказывает удаления по модулю
- Упаковывает трубы для создания больших свободных блоков
- Эффективен на структурированных тестах

### Режим 3: Периодический (Продвинутый)
- Выявляет полную периодичность входящих длин
- Делает предположение о паттерне удаления
- Адаптируется если предположение неверно
- Помогает на последовательностях с четкой структурой

### Режим 4: Выученный периодический
- Учится по реальным удалениям, какие позиции периода удаляют
- Остающиеся трубы не занимают дыры обречённых, обречённые переиспользуют их места
- Помогает, когда удаляют не чётные позиции периода, а произвольный набор

## 🎯 Метрики успеха

- **KPI** = (сумма длин оставшихся труб) / (длина траншеи)
- **Score** = Σ(KPI_i × weight_i) для всех 30 тестов
- Максимальный KPI на большинстве тестов близок к 1.0
- Критерий побеждающего решения: максимальный Score, затем минимальный CPU time

## 🔧 Компиляция и запуск

```bash
# Компиляция решения
g++ -O2 -std=c++17 solution.cpp -o solution

# Компиляция офлайн-анализатора  
g++ -O2 -std=c++17 offline.cpp -o offline

# Запуск на одном тесте
python runner.py -i tests/1.in ./solution

# Запуск на всех тестах (tests/ и myTests/) с итоговым KPI и CPU-временем
python run_all.py

# Быстрый прогон без интерактора: KPI в stderr
g++ -O2 -std=c++17 -DSIM solution.cpp -o solution_sim
./solution_sim < tests/15.in > /dev/null

# Локальная генерация тестов
python generate_tests.py

# Анализ стратегий с знанием будущего
./offline tests/*.in
```

## 📝 Примечания

- Решение использует техники предсказания и адаптации для максимизации KPI
- Критические компоненты: быстрое управление щелями, обнаружение паттернов, адаптивные стратегии
